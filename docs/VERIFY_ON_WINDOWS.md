# 在 Windows 上验证 EchoVoice

> WSL 里只能做 `cargo check`（没有 `link.exe`，构建不出 exe）。
> 音频核心的 97 个单测/集成测试在 Windows 上一样能跑，WASAPI 部分必须真机手测。

## 四、音频链路手测（按顺序，每步都有明确判据）

打开软件后先点左侧 **启动音频桥接**，侧边栏状态灯变绿。

### 4.1 麦克风直通（M1 地基）
1. 打开 Windows 设置 → 系统 → 声音 → 高级 → **更多声音设置** → 「录制」页
2. 双击 `CABLE Output (VB-Audio Virtual Cable)` → 「侦听」页 → 勾选「侦听此设备」
3. 对着麦克风说话 → **应该实时听到自己的声音**，延迟接近 0

> 不勾「侦听」也行，但你会听不到，只能用录音软件验证。

### 4.2 音效播放
1. 「+ 添加音效」导入一个 WAV/MP3
2. 点卡片上的 ▶ → **应该听到**，卡片边框变蓝，底部出现进度条
3. 再点一次 ■ → 停止

### 4.3 多音效叠加 + 重触发
1. 连点 3 个不同音效的 ▶ → **三个应该同时在响**（叠加，不是排队）
2. 长音效播放中再按它自己的快捷键 → **应该从头重新开始**，不是没反应

### 4.4 每音效音量 / 循环 / 按住播放 / 裁剪
点卡片上的 ⚙ 打开设置面板：
- **播放音量**拖到 20% → 播放，应该明显变小
- **循环播放**打勾 → 播放，应该无限循环不停
- **按住快捷键时才播放**打勾，绑定一个键 → 按住响、**松手立刻停**
- **裁剪**起点填 5000 → 播放，前 5 秒应该被跳过

### 4.5 麦克风闪避（Ducking）
「声音路由」页 → 勾选「播放音效时自动压低麦克风」，深度 50%
1. 播放一个 10 秒以上的音效
2. 同时对着麦克风持续说话
3. **说话声应该在音效播放期间被压低约 6 dB，音效结束立刻恢复**

### 4.6 降噪闸门
「声音路由」页 → 闸门拉到 3% 左右
1. 对着麦克风吹气/制造风扇声 → **应该听不到**
2. 正常说话 → **应该正常通过，且开头没有「咔」一下的断点**

### 4.7 软限幅
同时播放 5 个以上响度大的音效 + 大声说话
- **不应该出现硬截波的「噼啪」声**
- 「声音路由」页的「削波采样点数」计数器会涨，但听感应该是压紧而不是破音

### 4.8 音乐播放器
1. 左侧「音乐」页 → 导入几首歌
2. 在任意音效的 ⚙ 设置里勾选「用作音乐」，它们会出现在播放列表
3. 点列表序号播放 → 底部显示进度，播完**自动切下一首**
4. 播放中静音「音效台」→ **音乐应该继续响**（独立声道）
5. 音乐页绑定「播放/暂停」快捷键 → 游戏中按一下应该暂停/继续

## 五、游戏内快捷键（重点，你反馈过不好用）

### 5.1 先看诊断面板

「软件设置」页 → **游戏内快捷键诊断**，四格实时数据：

| 格子 | 正常值 | 异常说明 |
|---|---|---|
| 键盘监听 | 正常 | 「未运行」= 钩子没装上，重启软件 |
| 派发通道 | `keyboard-hook` | 如果是 `register-hotkey`，说明钩子没装上 |
| 是否以管理员运行 | 是/否 | **否 + 游戏是管理员 = 快捷键必然失效** |
| 已收到按键数 | 持续增长 | 不动 = 按键根本没到我们这里 |

### 5.2 30 秒定位法

1. 绑定一个快捷键，比如 `Ctrl+Shift+1`
2. **不要开游戏**，在桌面随便按 → 看「已收到按键数」有没有涨、音效有没有响
   - 不涨 → 绑定没成功，看顶部有没有红色错误条（大概率是快捷键冲突）
   - 涨但不响 → 音频链路问题，回去看第四章
3. **打开游戏**（或任何一个全屏应用，甚至记事本也行），切过去再按
   - 「已收到按键数」**不涨**了 → Windows 拦截，几乎一定是**提权问题**，看 5.3
   - 还在涨、也响 → 好的，游戏里应该也能用

### 5.3 提权（最常见的坑）

如果你的游戏以管理员运行，Windows **硬性禁止**普通进程接收发给它的按键——这不是 bug，是安全边界，用户态无解。

诊断面板检测到「未提权」时会弹出黄框，点 **「以管理员身份重启」** 即可（会弹 UAC，点是）。

> 以后每次开游戏前，建议直接把 EchoVoice 设为以管理员运行（右键 → 以管理员身份运行），
> 或者如果游戏不需要管理员，就把游戏的「以管理员运行此程序」勾掉。

### 5.4 为什么现在比之前可靠

- **只有一条派发通道**：低层键盘钩子是唯一通道。之前 `RegisterHotKey` 和钩子同时开会造成每次按键触发两次，用一个 80ms 时间窗去重——而那个时间窗又会吞掉你合法的快速连按。现在没有时间窗。
- 游戏自己会占键位（它也用 `RegisterHotKey`），低层钩子不受影响
- 能收到**松开事件**，所以「按住播放」才可能实现

## 六、设备断开自动重连

1. 桥接运行中，**拔掉 USB 麦克风/耳机**
2. 侧边栏状态灯应该变黄显示「正在重连 #N」，顶部出现提示
3. **插回去** → 应该自动恢复，状态灯变绿，不需要你点任何东西
4. 中途你手动点「停止音频桥接」→ 重连应该停止，不会跟你抢

---

## 七、托盘

- 点左上角 ✖ 关闭窗口 → 应该**缩到托盘**（不是退出）
- 托盘图标右键 → 切换桥接 / 全部停止 / 静音麦克风 / 静音音效台 / 退出
- 左键托盘图标 → 显示窗口

---

## 八、配置持久化

改一堆设置（音量、EQ、快捷键、主题、开机自启）→ 退出软件 → 重开
**所有设置应该原样恢复**。配置文件在：

```
%LOCALAPPDATA%\com.echovoice.app\echovoice_config.json
```

直接编辑这个 JSON 再启动也应该生效（未知字段会被忽略，不会崩）。

---

## 九、性能与稳定性

- **首次按键延迟**：桥接启动时所有音效已预解码，游戏中第一次按和第 10 次应该一样快
- **长时间运行**：挂着 2 小时，切歌/放音效/说话，内存不应该持续增长
- **CPU**：空闲时应该接近 0（遥测线程 4Hz，音频线程阻塞等待）

## 十、从 WSL 里启动 Windows 上的 exe（小技巧）

如果你在 Windows 上构建过一次，可以从 WSL 直接跑：

```bash
# 假设项目在 C:\code\rust\EchoVoice
/mnt/c/code/rust/EchoVoice/src-tauri/target/release/echovoice.exe
```

WSL2 有 `.exe` interop，GUI 程序会正常在 Windows 桌面上弹出。
（但**编译**还是必须在 Windows 做，WSL 缺 `link.exe`。）
